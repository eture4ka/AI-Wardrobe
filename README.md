# SmartWardrobe — гардероб з AI-стилістом

Оцифруй гардероб → зрозумій свій стиль → створюй образи → вирішуй, чи варто купувати → оживляй забуті речі → проходь fashion-челенджі.

Навчальний прототип з предмета «Основи підприємництва та бізнес-планування в ІТ».

## Що вміє

| Функція | Як працює |
|---|---|
| **Реєстрація й анкета стилю** | При першому запуску: акаунт (ім'я, email, телефон, вік, стать), параметри (зріст, розміри, місто), анкета з 5 питань про стиль і фото для примірки |
| **Оцифровка гардеробу** | Фотографуєте річ — AI визначає назву, категорію, колір, стиль, сезон і теплоту |
| **Образ + погода + місце** | Вписуєте місто, застосунок сам підтягує поточну температуру й погоду, далі AI збирає 3 образи під подію |
| **Мій стиль** | AI аналізує гардероб і формує профіль: стиль, улюблені кольори, що носите найчастіше. Далі це враховується в підборі |
| **Купувати чи ні?** | Фото речі в магазині + ціна → скільки у вас схожих, скільки нових комбінацій додасть, ціна за комбінацію, вердикт і приклади образів. Ціна порівнюється із середньою ціною вашого гардеробу |
| **Забуті речі** | Показує, що давно не було в образах, і генерує для цих речей нові комбінації |
| **Розумна валіза** | Місто + кількість днів → прогноз погоди → образи на кожен день з мінімуму речей |
| **Примірка на мені** | Експеримент: генерує фото образу на вашому фото. Потребує моделі з генерацією зображень |
| **Челенджі й рівні** | 4 челенджі, бали та рівні Style Beginner → Fashion Explorer → Smart Stylist → Style Master |
| **Що докупити** | Вказуєте максимальну ціну → AI пропонує 3 речі в межах цієї суми, код рахує, скільки комбінацій кожна відкриє, а кнопка відкриває пошук по товарах із фільтром «не дорожче N грн»: там видно саме ті магазини, де річ є за цю ціну. Це реалізація партнерської бізнес-моделі |
| **Вартість носіння** | Вказали ціну — застосунок рахує, скільки коштує одне носіння кожної речі |

## Запуск у VS Code

1. Відкрийте цю папку у VS Code (File → Open Folder).
2. Встановіть розширення **Live Server** (автор Ritwick Dey).
3. Правою кнопкою на `index.html` → **Open with Live Server**.
4. Натисніть 🔑 угорі та вставте API-ключ Gemini.

Без ключа працює все, крім AI: можна додавати речі вручну й завантажити демо-гардероб.

## Безкоштовний API-ключ

1. Зайдіть на https://aistudio.google.com і увійдіть через Google-акаунт.
2. **Get API key** → **Create API key**.
3. Скопіюйте ключ (`AIza...`) і вставте в застосунок через 🔑.

Картка не потрібна. Безкоштовний тариф має денний ліміт запитів — для демонстрації вистачає. Погода береться з Open-Meteo, яка теж не потребує ключа.

**Моделі визначаються автоматично.** Застосунок питає у Google, які моделі доступні саме вашому ключу, і обирає відповідні. Список обраних моделей видно у вікні 🔑 — зручно перевірити перед захистом. Якщо Google згодом замінить моделі, нічого правити не треба; за потреби порядок переваг задається в `MODEL_PREFS` у коді.

## Демонстрація на захисті

0. **Перший запуск** — пройти реєстрацію та анкету стилю (близько хвилини). Щоб показати онбординг ще раз, натисніть «Скинути все» у профілі.
1. **Завантажити приклад** — з'явиться гардероб з 13 речей і реальною історією носіння: видно вартість носіння кожної речі та 6 речей, які давно без діла.
2. **Профіль → Проаналізувати мій стиль** — AI описує стиль користувача.
3. **Підібрати** — вписати своє місто, натиснути «Погода», обрати подію, згенерувати образи.
4. **Купувати?** — сфотографувати будь-яку річ, вписати адекватну ціну, потім свідомо завищену й натиснути «Перерахувати». Вердикт зміниться з «Варто купити» на «Краще пропустити» — ефектний момент для захисту.
5. **Профіль → забуті речі** — натиснути на річ, застосунок складе образи саме з нею.
6. **Челенджі** — почати один і показати прогрес.
7. **Профіль → Що докупити** — вписати 2000 грн і показати, що застосунок радить лише те, що вкладається в цю суму, і одразу відкриває магазини з фільтром за ціною. Це видимий доказ бізнес-моделі.

Перед захистом прогоніть сценарій один раз, щоб не витрачати денний ліміт наживо.

## Безпека

Ключ зберігається лише в браузері користувача (localStorage) і не записаний у коді, тому репозиторій можна публікувати. Для навчального прототипу цього достатньо, але у справжньому продукті запити до AI мають іти через власний сервер — інакше ключ видно в браузері. Це хороший пункт для слайда з ризиками та дорожньої карти.

## Структура коду

Код поділений на шари. **Правило: шар може викликати те, що під ним, але ніколи те, що над ним.**

```
index.html              розмітка
css/styles.css          оформлення
js/
  config.js     шар 1   довідники, анкета, челенджі, демо-гардероб — тільки дані
  store.js      шар 2   стан, збереження в localStorage, дії над станом
  logic.js      шар 3   чисті обчислення: вартість носіння, комбінації, прогрес
  api/gemini.js шар 4   спілкування з AI
  api/weather.js шар 4  погода з Open-Meteo
  prompts.js    шар 5   усі запити до AI в одному місці
  ui.js         шар 6   малювання екранів
  app.js        шар 7   обробники подій, сценарії функцій, запуск
```

У файлах `config`, `logic`, `prompts` і `api` немає жодного `document` — перевіряється пошуком.

Стан змінюється тільки через `Store.update()`, який зберігає дані й сам повідомляє інтерфейс:

```js
Store.subscribe(renderAll);              // один раз при запуску
Store.update(s => { s.points += 10 });   // інтерфейс перемалюється сам
```

Порядок підключення файлів у `index.html` важливий: нижні шари мають завантажитися першими.
