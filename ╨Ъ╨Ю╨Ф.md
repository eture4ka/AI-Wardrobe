# Що показує код SmartWardrobe

Шпаргалка для захисту: що відкрити в редакторі, що сказати і на яке питання це відповідає.

Проєкт поділений на шари — кожен файл відповідає за один рівень:

```
index.html          розмітка
css/styles.css      оформлення
js/config.js        шар 1  конфігурація — тільки дані
js/store.js         шар 2  стан і сховище
js/logic.js         шар 3  чисті обчислення
js/api/gemini.js    шар 4  зовнішній сервіс: AI
js/api/weather.js   шар 4  зовнішній сервіс: погода
js/prompts.js       шар 5  запити до AI
js/ui.js            шар 6  малювання екранів
js/app.js           шар 7  обробники подій і запуск
```

**Головне правило: шар може викликати те, що під ним, але ніколи те, що над ним.** У файлах `config`, `logic`, `prompts` і `api` немає жодного слова `document` — це можна перевірити пошуком прямо на захисті.

---

## 1. Архітектура: як влаштований застосунок

**Показати:** `js/store.js`.

```js
const state={ items:[], outfits:[], wearLog:[], profile:null, points:0,
              challenges:{}, city:"", userPhoto:null, user:null, ... };
```

```js
const Store={
  subscribe(fn){listeners.push(fn)},          // інтерфейс підписується на зміни
  update(mutator){
    if(mutator)mutator(state);                // змінюємо дані
    const ok=Store.save();                    // зберігаємо
    listeners.forEach(fn=>fn(state));         // повідомляємо інтерфейс
    return ok;
  }, ...
};
```

**Що сказати:** застосунок побудований навколо одного об'єкта `state` — це вся пам'ять програми. Змінити його можна тільки через `Store.update()`: він зберігає дані й сам повідомляє інтерфейс. Інтерфейс нічого не зберігає й нічого не рахує — він лише реагує на зміну стану. Це односпрямований потік даних, той самий принцип, на якому побудовані React і Vue, тільки в мініатюрі й без бібліотек.

**Відповідає на питання:** «Як у вас організовані дані?»

## 2. Реєстрація та анкета стилю

**Показати:** масив `QUIZ` у `js/config.js` і функцію `obRender()` у `js/app.js`.

```js
const QUIZ=[
  {id:"vibe", q:"Який образ вам ближчий?", multi:false,
   opts:[["min","Мінімалізм","🤍"],["classic","Класика","🧥"], ...]},
  ...
];
```

**Що сказати:** анкета описана даними, а не кодом. Щоб додати нове питання, достатньо дописати один рядок у масив `QUIZ` — інтерфейс, індикатор прогресу й збереження підхопляться самі. Саме так додалося питання про візерунки: жодного нового коду, тільки новий елемент масиву, і воно одразу з'явилося в анкеті, у профілі та в запитах до AI. Плитки малюються з CSS-градієнтів, без жодного чужого фото. Це приклад підходу «дані замість коду»: логіка написана один раз і працює з будь-якою кількістю питань.

**Відповідає на питання:** «Наскільки легко розвивати ваш продукт?»

## 3. Головне: анкета реально впливає на AI

**Показати:** `js/prompts.js` — функції `userContext()` та `Prompts.outfits()`.

```js
function userContext(){
  // збирає ім'я, вік, стать, зріст, розміри та всі відповіді анкети
  return `ПРО КОРИСТУВАЧА (враховуй це в порадах): ...`;
}

// prompts.js — сам запит
outfits({event,temp,weather,city,profile,force,catalog}){
  return `Ти AI-стиліст застосунку-гардеробу. Склади 3 різні образи ТІЛЬКИ з речей користувача нижче.
${userContext()}
Умови: подія — ${event}; температура ${temp}C; погода — ${weather}...
Речі: ${catalog}`;
}

// app.js — виклик
const prompt=Prompts.outfits({
  event:state.event, temp:tempLabel(temp), weather:state.weather,
  city:state.city, profile:state.profile, force, catalog:catalogText(state.items)
});
```

**Що сказати:** усі запити до AI зібрані в одному файлі `prompts.js` — це серце продукту, і його можна вдосконалювати, не чіпаючи решту коду. Ми не просто зберігаємо анкету «для галочки» — вона підставляється в кожен запит до AI разом з каталогом речей, погодою та подією. Тому дві людини з однаковим гардеробом отримають різні поради. Саме це відрізняє нас від конкурентів, які підбирають образи «взагалі», а не під конкретну людину.

**Відповідає на питання:** «Навіщо анкета, якщо AI і так розумний?»

## 4. Робота з AI: захист від збоїв

**Показати:** `js/api/gemini.js` — функції `loadModels()`, `callGemini()`, `parseJSON()`, `aiCopy()`.

```js
if(res.status===404&&!retried){
  await loadModels(true);                       // назва моделі застаріла
  if(MODELS[role]&&MODELS[role]!==model)
    return callGemini(role,parts,cfg,signal,true); // пробуємо ще раз
}
```

**Що сказати:** застосунок не покладається на жорстко прописану назву моделі. Він питає у Google, які моделі доступні цьому ключу, і обирає відповідну. Якщо модель зникне, код автоматично оновить список і повторить запит. Крім того, функція `aiCopy()` перекладає технічні помилки на зрозумілу мову: замість «429» користувач бачить «вичерпано ліміт запитів, спробуйте пізніше».

**Відповідає на питання:** «А що буде, якщо AI відповість помилкою?» — це прямо пов'язано зі слайдом технічних ризиків.

## 5. Аналітика гардеробу: чесна математика

**Показати:** `js/logic.js` — функції `costPerWear()`, `newCombos()`, `forgottenItems()`.

```js
function costPerWear(it){
  if(!it.price||!(it.wearCount>0))return null;
  return Math.round(it.price/it.wearCount);   // вартість одного носіння
}

function newCombos(cat){                       // скільки комбінацій додасть річ
  const n=c=>state.items.filter(i=>i.category===c).length;
  const shoes=Math.max(1,n("shoes"));
  if(cat==="top")return n("bottom")*shoes;
  ...
}
```

**Що сказати:** цифри на екрані рахує наш код, а не вигадує AI. AI відповідає за текст і розпізнавання, а числа — вартість носіння, кількість комбінацій, кількість забутих речей — обчислюються формулами. Це принципово: якби числа вигадував AI, їм не можна було б довіряти.

**Відповідає на питання:** «Звідки беруться ці цифри, ви їх не вигадали?»

## 6. «Купувати чи ні» — ціна керує вердиктом

**Показати:** `Prompts.buy()` у `js/prompts.js` і обробник `$("#buyGo").onclick` у `js/app.js`.

```js
const priced=state.items.filter(i=>i.price>0);
const avg=priced.length?Math.round(priced.reduce((a,i)=>a+i.price,0)/priced.length):0;

const priceBlock=price
  ? `Ціна речі: ${price} грн. Середня ціна речі в гардеробі: ${avg} грн.
     ЦІНА — ГОЛОВНИЙ ЧИННИК ВЕРДИКТУ...`
  : `Ціна невідома — оцінюй лише за користю для гардеробу...`;
```

**Що сказати:** ми рахуємо середню ціну речі саме цього користувача й передаємо її AI як орієнтир. Тому дорога річ для студента і для людини з дорогим гардеробом оцінюються по-різному. Це можна показати наживо: та сама річ з ціною 1200 грн отримує «Варто купити», а з ціною 100 000 грн — «Краще пропустити».

**Відповідає на питання:** «Чим ваш застосунок корисний бізнесу і користувачу одночасно?»

## 8. Погода без ключа

**Що сказати:** погоду беремо з Open-Meteo — безкоштовного сервісу, який не потребує ключа й оплати. Спершу перетворюємо назву міста на координати, потім отримуємо температуру й код погоди, який переводимо у зрозумілі категорії: сонячно, дощ, сніг, вітер. Це знижує собівартість продукту.

## 9. Безпека: що тут зроблено правильно, а що — ні

**Показати:** функцію `getKey()` у `js/api/gemini.js`.

```js
const getKey=()=>{try{return localStorage.getItem(KEY_LS)||""}catch(e){return ""}};
```

**Що сказати чесно:** ключ до AI зберігається в браузері користувача й не записаний у коді — тому репозиторій можна публікувати. Але для справжнього продукту цього замало: запити до AI мають іти через власний сервер, інакше ключ видно в браузері. Ми це усвідомлюємо, і перехід на власний бекенд стоїть окремим пунктом у дорожній карті.

**Відповідає на питання:** «Які у вас технічні ризики?» Визнати обмеження прототипу сильніше, ніж вдавати, що їх немає.

## 10. Бізнес-модель, яку видно в коді

**Показати:** `SHOPS` у `js/config.js`, `shopSearchUrl()` у `js/logic.js`, `Prompts.gaps()` у `js/prompts.js`.

```js
// config.js — магазини-партнери
const SHOPS=[{name:"Rozetka",site:"rozetka.com.ua"}, ..., {name:"Всі. Свої",site:"vsisvoi.ua"}];

// logic.js — побудова посилання з фільтром ціни
function shopSearchUrl(query,site,maxPrice){
  const withCap=q+(cap?` до ${cap} грн`:"");
  if(site)return "https://www.google.com/search?hl=uk&gl=ua&q="+encodeURIComponent(withCap+" site:"+site);
  let url="https://www.google.com/search?tbm=shop&hl=uk&gl=ua&q="+encodeURIComponent(withCap);
  if(cap)url+="&tbs="+encodeURIComponent("mr:1,price:1,ppr_max:"+cap);  // не дорожче cap
  return url;
}
```

**Що сказати:** користувач вказує максимальну ціну, і вона йде у двох напрямках: у промпт, щоб AI пропонував лише те, що в неї вкладається, і у фільтр пошуку по товарах, щоб показати саме ті магазини, де річ є за цю ціну або дешевше. Крім великих маркетплейсів у списку є майданчики українських дизайнерів, а якщо користувач вказав місто — з'являється кнопка пошуку в магазинах його міста. Застосунок радить купити річ лише тоді, коли порахував, скільки нових образів вона відкриє — число рахує наш код. Далі він веде користувача в магазин. Це і є партнерська модель: щоб почати заробляти, достатньо додати код партнера до цих самих посилань, коли буде підписана угода з магазином.

**Що визнати чесно:** зараз посилання звичайні, не партнерські, і прямої інтеграції з каталогами магазинів немає — для неї потрібні API магазинів і власний сервер. Це записано в дорожній карті.

**Відповідає на питання:** «Ви кажете, що заробляєте на комісії — а де це в продукті?»

## 11. Дві лінії доходу: підписка і комісія

**Показати:** `PLAN` у `js/config.js` і функції `canUse()`, `itemLimit()`, `styleLimit()` у `js/logic.js`.

```js
// config.js — усі правила тарифу в одному місці
const PLAN={
  price:149, freeItems:30, freeStyles:1, premiumStyles:3,
  premiumOnly:{buy:"...", tryon:"...", pack:"..."}   // «Що докупити» навмисно не тут
};

// logic.js — одна перевірка для всього застосунку
const canUse=feature=>isPremium()||!PLAN.premiumOnly[feature];
```

**Що сказати:** правила тарифу описані даними, як і анкета. Щоб перенести функцію в Premium або змінити ліміт, досить змінити один рядок у `PLAN` — інтерфейс, значки «Premium» і вікно оплати підлаштуються самі. «Що докупити» навмисно безкоштовне: безкоштовні користувачі приносять дохід через комісію з покупок, платні — через підписку.

**Що визнати чесно:** оплата не підключена, Premium вмикається демо-кнопкою. Для справжньої оплати потрібні платіжний сервіс і сервер, щоб підписку не можна було ввімкнути в браузері вручну.

**Відповідає на питання:** «Як саме ви заробляєте?»

## Короткий сценарій демонстрації коду (3–4 хвилини)

1. Показати дерево файлів і пояснити шари одним реченням (пункт 1).
2. `store.js` — `Store.update()` і підписка: як дані керують інтерфейсом (пункт 1).
3. `config.js` — масив `QUIZ`: анкета описана даними (пункт 2).
4. `prompts.js` — `userContext()`: анкета йде в кожен запит до AI (пункт 3). Це головний козир.
5. `logic.js` — `costPerWear()` і `newCombos()`: числа рахує код, а не AI (пункт 5).
6. `config.js` — `SHOPS` і `shopSearchUrl()`: бізнес-модель у коді (пункт 10).
7. Перемкнутися в браузер і показати той самий сценарій наживо.

## Статистика проєкту

- Без сторонніх бібліотек і фреймворків — чистий JavaScript.
- Два зовнішні сервіси: Google Gemini (AI) та Open-Meteo (погода).
